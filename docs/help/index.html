1. Introduction & purpose

Shigley Solver Pack streamlines the execution and documentation of mechanical design calculations derived from Shigley's Mechanical Engineering Design. The application unifies natural-language problem intelligence, curated solver implementations, and modern reporting so that engineering teams can:

  • Accelerate textbook-style problem solving through automated class detection and data extraction.
  • Execute deterministic solvers with repeatable validation and rich explanations.
  • Generate auditable records, including SI-based payloads and printable narratives, suitable for design reviews, coursework, or knowledge capture.

This manual is intended for engineering students, analysts, and educators who require both rapid answers and transparent documentation. It covers functional workflows, data standards, architectural concepts, troubleshooting, and support procedures for long-term operation.

2. System requirements & installation

Supported platforms

  • Windows 10/11, macOS 12+, or modern Linux distribution.
  • Python 3.10 or newer, configured with pip access.
  • Optional: Microsoft HTML Help Workshop for compiling the CHM manual.

Installation steps

  1. Clone or extract the repository into a writable workspace.
  2. Create a virtual environment and activate it.
  3. Install dependencies via pip install -r requirements.txt.
  4. Launch the application with streamlit run ui/app_manual_solver.py.
  5. (Optional) For natural-language parsing, install the problem_parsing_env components as documented in the README.

Browser & security considerations

  • Use a Chromium-based or Firefox browser to ensure MathJax rendering and printing fidelity.
  • Permit pop-ups for the Streamlit host to enable report and manual windows.
  • Network access is required for MathJax CDN resources unless served locally.

3. Platform architecture overview

The Shigley Solver Pack is organized into modular layers that separate presentation, orchestration, and domain logic.

  1. Presentation layer (Streamlit UI): Delivers the interactive application, manages session state, theme controls, and all reporting utilities.
  2. Solver registry: Each solver in solvers/ is registered with metadata, input schema expectations, and docstrings that explain formula provenance and assumptions.
  3. Natural-language pipeline (optional): The problem_parsing_env package performs class identification and structured data extraction using NLP models. The UI gracefully degrades if this package is absent.
  4. Documentation assets: The help manual, solver catalog, and inline explanations all share terminology and refer back to the Shigley text.

Separation of concerns allows teams to extend solver logic, update the NLP model, or rebrand the interface without destabilizing the rest of the system. Continuous integration test suites should target solver correctness and unit conversions wherever new functionality is introduced.

5. Quick start & recommended workflow

  1. Launch the Streamlit interface and select a theme for readability.
  2. Review the solver catalog to familiarize yourself with available computations.
  3. Start with the Auto Solve tab for rapid validation, then refine or audit via the manual workspace.
  4. Capture clarifications or design notes in the dedicated problem statement fields; they flow into printable reports.
  5. Download SI JSON results and archive them alongside project deliverables.

Tip: Use version control or structured storage (e.g., SharePoint, Git) to track input payloads, outputs, and report PDFs for each design iteration.

6. Natural-Language auto-solver pipeline

  1. Paste the full problem statement, including all numeric data and units, into the provided text area.
  2. Review the suggested solver class, confidence score, and structured inputs. Use the assumptions and ambiguities panels to identify missing information.
  3. Trigger Solve automatically. The system first tries the NLP solution path and falls back to the manual registry if necessary.
  4. Assess the results, explanation narrative, and print-ready report. Adjust inputs manually if additional context is required.

The parser is trained on English textbook patterns. For multilingual input, supply a precise English draft or bypass the auto-solver and use the manual tab.

7. Manual JSON solver workspace & validation

  1. Select a solver class; type to filter by name or topic.
  2. Study the documentation block sourced from the solver description or the solver’s docstring.
  3. Customize the JSON payload. Use structured quantity dictionaries whenever unit provenance must be documented.
  4. Record the engineering narrative in the problem statement field to propagate it into reports.
  5. Execute the solver. Any exceptions surface in the UI; review numeric domains, required fields, and solver assumptions to resolve them.

Validation best practices include peer review of JSON payloads, automated unit tests for bespoke solvers, and cross-checking results against hand calculations or authoritative examples from the Shigley text.

8. Units, data management & versioning

All internal computations are performed in SI units. Quantity dictionaries capture the original engineering notation while standardizing the calculation base. 

{
  "material": {
    "E": {"value": 210.0, "unit": "GPa", "si": 210000000000.0},
    "S_y": {"value": 350.0, "unit": "MPa", "si": 350000000.0}
  },
  "loads": {
    "M": {"value": 2.8, "unit": "kN·m", "si": 2800.0},
    "T": {"value": 1.6, "unit": "kN·m", "si": 1600.0}
  }
}

Recommended data management practices:

  • Maintain a library of canonical payloads for recurring design scenarios.
  • Store solver outputs (JSON and PDF) under revision-controlled directories.
  • Synchronize manual notes with laboratory notebooks or collaborative design platforms to ensure traceability.

9. Reporting, narratives & printing

Each solver run surfaces a comprehensive report bundle:

  1. Results (JSON): Downloaded via the UI, containing raw SI outputs and any intermediate values provided by the solver.
  2. Solution explanation: MathJax-rendered narrative that can be quoted in design logs or presentations.
  3. Print full report: Launches a dedicated window that collates the problem statement, parsed inputs, assumptions, results, and references. Use the browser print dialog to export to PDF or hardcopy.

Reports inherit the selected theme for visual consistency. For submission to external stakeholders, the Monochrome theme yields the cleanest print output.

11. Analytical formula reference

The following selection highlights representative expressions implemented across the solver suite. Consult the solver source for full derivations and assumptions.

Domain Expression Key variables
Beam bending (UDL) \( M_{max} = \tfrac{q L^2}{8}, \quad \delta_{mid} = \tfrac{5 q L^4}{384 E I} \) \(q\) uniform load, \(L\) span, \(E\) modulus, \(I\) inertia.
Euler column buckling \( P_{cr} = \frac{\pi^2 E I}{(K L)^2} \) \(K\) effective length factor, \(L\) unsupported length.
Johnson column buckling \( P_{cr} = A S_y \left[1 - \frac{S_y}{2 \pi^2 E} \lambda^2 \right] \), \( \lambda = \frac{K L}{r} \) \(A\) area, \(r\) radius of gyration, \(S_y\) yield strength.
Power screw torque \( T_{total} = \tfrac{F d_m}{2} \tan(\alpha + \phi) + \tfrac{F \mu_{collar} d_{collar}}{2} \) \(d_m\) mean diameter, \(\alpha\) lead angle, \(\phi\) friction angle.
Shaft torsion \( \tau_{max} = \tfrac{16 T}{\pi d^3}, \quad \theta = \tfrac{T L}{G J} \) \(d\) diameter, \(G\) shear modulus, \(J\) polar inertia.
Von Mises criterion \( \sigma_{eq} = \sqrt{\tfrac{1}{2}[(\sigma_x-\sigma_y)^2 + (\sigma_y-\sigma_z)^2 + (\sigma_z-\sigma_x)^2] + 3(\tau_{xy}^2+\tau_{yz}^2+\tau_{zx}^2)} \) Principal stresses or stress tensor components.
Modified Goodman fatigue \( \frac{\sigma_a}{S_e} + \frac{\sigma_m}{S_{ut}} = \frac{1}{n} \) \(S_e\) endurance limit, \(S_{ut}\) ultimate strength, \(n\) design factor.
Rolling bearing L10 life \( L_{10} = a_1 \left(\frac{C}{P}\right)^p 10^6 \) \(a_1\) reliability factor, \(C\) capacity, \(P\) equivalent load, \(p\) exponent.
AGMA contact stress \( \sigma_H = Z_e \sqrt{\tfrac{W_t K_o K_v K_s K_m C_f}{b d_p I}} \) Geometry factors \(I\), face width \(b\), tangential load \(W_t\), material factor \(Z_e\).

13. Themes, accessibility & productivity tips

  • Modern Light: Balanced contrast suited for projected demonstrations and general use.
  • Monochrome: Optimized for grayscale printing and photocopying.
  • Midnight Dark: Low-glare option for extended review sessions or dim environments.

Accessibility recommendations include enabling browser zoom controls, using the manual problem statement field for screen-reader-friendly narration, and exporting JSON data for integration with custom accessibility tooling.

Productivity tips:

  • Save common payloads in a local snippet manager for rapid reuse via copy/paste.
  • Pair solver outputs with plotting libraries (e.g., Matplotlib, Plotly) to visualize stress envelopes or life curves.
  • Embed JSON downloads in Jupyter notebooks for exploratory calculations or Monte Carlo extensions.

14. Troubleshooting & diagnostics

Common symptoms

  • Solver returned no results: Verify required fields, confirm JSON syntax, and review solver assumptions.
  • NLP parser unavailable: Install or repair the problem_parsing_env package.
  • Report window blocked: Allow pop-ups or add the Streamlit host to your browser’s exceptions list.
  • Math not rendering: Ensure MathJax scripts load (network policy) or host MathJax locally.

Diagnostic workflow

  1. Reproduce the issue using a minimal JSON payload or a known-good sample.
  2. Inspect the Streamlit server log for stack traces when solver execution fails.
  3. Leverage unit tests in tests/ to confirm solver invariants remain intact after modifications.
  4. Document findings in the problem statement or project tracker for future reference.
